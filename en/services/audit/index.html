Audit and project rescue

The project is on fire: deadlines passed, the vendor vanished, release is not getting closer. We start with facts, not a rewrite: what works, what is broken, what it costs to reach release. A prioritised report in 1–2 weeks.

Discuss the taskPackages and pricing

What we do

  • Code audit: quality, dependencies, tests, critical spots
  • Architecture audit: bottlenecks, scaling, risks
  • Security audit: access, secrets, data handling (not infrastructure pentesting)
  • Prioritised report: fix now versus later
  • Rescue plan and a release estimate

Who it is for

  • Companies whose project stalled or whose vendor disappeared
  • Investors and founders before putting money into someone else's code
  • Products before scaling or changing teams
  • Teams that need an outside look at the architecture

Scope of work

  • Repository and environment access (read-only where possible)
  • Interviews with the team and incident review
  • Report: findings, risks, priorities, effort estimate
  • Results presentation and action plan
  • Optionally, delivery to release as a separate project

FAQ

Common questions

What is included in a $2,000 audit?
A fixed scope: one repository, one service, a prioritised report and a work plan. For larger projects we propose an extended scope and a separate estimate.
Do you rewrite the whole project?
Only if that is cheaper than fixing it. We usually start with surgery: close critical risks, stabilise the release, then tidy up.
Do you work with undocumented foreign code?
Yes, that is the typical case. We start with a dependency map and a local run; if the project does not start, that is the first finding.
